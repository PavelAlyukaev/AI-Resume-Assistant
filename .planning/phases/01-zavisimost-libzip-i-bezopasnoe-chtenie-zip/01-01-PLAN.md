<objective>
Make libzip a buildable, testable and deployable dependency, and prove one byte-exact read of word/document.xml from an in-memory ZIP. This plan is the Phase 1 tracer slice: the thinnest end-to-end path through every layer this plan touches (CMake, libzip, the documents layer, Qt Test, ctest, CI, deploy). It is production code that later plans extend, not a prototype.

Purpose: ROADMAP success criteria 1 and 2 (clean build with libzip, installed folder starts without missing DLLs) depend on this plan. SAFE-01 and SAFE-02 appear in this plan's requirements as the foundation only: the buffer-only open with no path API, the budgeted read, and the Corrupt mapping at open. Their complete behavior lands in plan 01-02 (SAFE-01 classification), plan 01-03 (SAFE-01 application texts) and plan 01-04 (SAFE-02 limits).

Output: resume_documents static library (DocxTypes.h, ZipArchive), zip_archive Qt Test target, libzip in both CI install lists, libzip.dll and its transitive DLLs in the installed folder.

Gate and order: Task 1 is a blocking-human checkpoint for the single new package (required by the package legitimacy gate). It is a gate, not a work slice, so the leading work task is Task 2, the tracer. Task 3 extends the tracer to CI and to the installed folder.

Reversibility: no decision in this plan is one-way. Nothing on disk changes format, no published API is exposed, and no data is written. The libzip choice and the ZipArchive shape are rated costly and flagged on Task 2. No checkpoint:decision is inserted.

Known deviation from 01-RESEARCH.md: the research expected no change to cmake/DeployMinGWRuntime.cmake. That is likely wrong. GET_RUNTIME_DEPENDENCIES resolves only DLLs reachable from the scanned executables, and no Phase 1 code calls libzip from the application executable, so the linker should record no import of libzip.dll. Task 3 therefore installs libzip.dll explicitly and scans it. Task 3 checks the premise with objdump before and after the change instead of assuming it.

Decisions implemented here (see 01-CONTEXT.md): D-02 (the 20 MiB unpacked budget is the mechanism introduced by readEntry maxBytes; the numeric value is pinned in plan 01-02), D-07 (a failed entry read returns no partial bytes), D-10 (the library opens only with ZIP_RDONLY from memory and writes nothing).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-selected file bytes to ZipArchive (libzip parser) | Untrusted ZIP bytes are parsed by a C library; the first place where hostile input meets native code |
| MSYS2 mingw64/bin to the installed application folder | DLLs are copied at install time and load at launch |
| MSYS2 package repository to the developer machine | Third-party binary package installed with pacman (supply chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | libzip.dll and transitive DLLs at install time | medium | mitigate | Copy DLLs only from the MSYS2 mingw64/bin prefix (install rule and GET_RUNTIME_DEPENDENCIES). Task 3 checks that each non-system DLL imported by libzip.dll exists in the install prefix. No wildcard or version-named DLL masks. |
| T-01-02 | Denial of service | ZipArchive::readEntry on a hostile entry | high | mitigate | readEntry takes maxBytes, reads in 64 KiB chunks through the fread function, and returns Limit before the running total exceeds maxBytes. Full zip-bomb defenses land in plan 01-04. |
| T-01-03 | Tampering | Wrong file read for a Cyrillic path through the narrow path-based open | low | mitigate | The documents layer accepts only QByteArray. No function in ZipArchive takes a path. Plan 01-03 reads the file with QFile. |
| T-01-04 | Information Disclosure | libzip error text reaching UI or logs | low | mitigate | ZipArchive maps libzip failures to DocxError codes and never stores or returns message text. |
| T-01-SC | Tampering | Package install: mingw-w64-x86_64-libzip from MSYS2 (supply chain) | high | mitigate | Package-legitimacy gate: Task 1 is a blocking-human checkpoint (gate blocking-human) that verifies the package page, license and upstream before pacman runs. The research table in 01-RESEARCH.md is present. |

(2) src/documents/DocxTypes.h: include guard with pragma once; namespace documents; enum class DocxError with the values NotZip, Corrupt, Encrypted, LegacyDoc, TooLarge, Limit, MissingPart. Add a comment that the file holds codes only and that user-facing texts live in the application layer (D-04, D-05).

(3) src/documents/ZipArchive.h: class documents::ZipArchive with a private implementation struct (pimpl) declared here and defined in the .cpp, so no libzip type or header appears in this header. Public interface: a static open function that takes a QByteArray by value and returns std::expected whose value is a std::unique_ptr to ZipArchive and whose error is DocxError; a const function hasEntry taking std::string_view for an exact entry name; a const function readEntry taking std::string_view for the exact name and a qint64 maxBytes budget, returning std::expected whose value is QByteArray and whose error is DocxError. The copy constructor and copy assignment are deleted. The destructor is declared here and defined in the .cpp. The constructor is private.

(4) src/documents/ZipArchive.cpp, open: move the bytes into the implementation struct first. Create the buffer source with the buffer-source function, passing constData of the owned bytes, the byte count, and freep 0, so the QByteArray owns the memory. Open it with the from-source open function using ZIP_RDONLY combined with ZIP_CHECKCONS. Never call the path-based open function, because a Cyrillic path breaks on MinGW (research Pitfall 2, D-05). When the buffer source or the from-source open returns null, return DocxError::Corrupt. Do not call the source-free function after a failed from-source open. The upstream documentation does not state who owns the source after a failed open, and a leaked small struct is preferable to a double free. Record this in the Task 3 memory note of plan 01-04. Use only constData on the owned bytes, never a non-const accessor, so the buffer can never detach or move while libzip reads it.

(5) src/documents/ZipArchive.cpp, destructor and lifetime: the destructor body closes the archive first (the discard function), then the implementation members are released, so the buffer outlives every libzip call. This is the RAII ordering from research Pattern 1 and Pitfall 7.

(6) src/documents/ZipArchive.cpp, readEntry: look up the exact name with the name-locate function using flags zero (case-sensitive, no case-insensitive flag). Not found returns DocxError::MissingPart. Open the entry by index with the fopen-index function; a null result returns DocxError::Corrupt for now in this tracer and is refined to Encrypted in plan 01-02. Read in chunks of 64 KiB with the fread function. Before appending a chunk, if the running total plus the chunk would exceed maxBytes, close the entry and return DocxError::Limit. A negative fread result returns Corrupt. A zero result ends the loop. Close with the fclose function; a nonzero close result returns Corrupt, so a checksum mismatch surfaces here and no partial bytes are returned (D-07). Never call any libzip function that returns message text, and never store message text (T-01-04). Declared sizes from the central directory are not used for allocation (research Pitfall 3).

(7) tests/ZipArchiveTest.cpp: class ZipArchiveTest deriving from QObject with Q_OBJECT, a private slots section, QTEST_GUILESS_MAIN, and the moc include at the end. Keep the fixture builders inside this file for now. Write a CRC-32 function (bitwise, reflected polynomial 0xEDB88320), and a stored-ZIP builder that takes a list of name and byte pairs and writes local file headers, the central directory and the end-of-central-directory record with method 0 (stored), little-endian fields, correct CRC and sizes. Add a helper that places bytes under word/document.xml next to a minimal [Content_Types].xml entry. Use no binary fixture files (research Pitfall 10). Test functions: openAndReadExactEntry (the body of word/document.xml contains Cyrillic text, and readEntry returns the identical bytes); readEntryEnforcesByteBudget (a budget one byte smaller than the entry gives DocxError::Limit); exactNameMissingIsMissingPart (asking for WORD/document.xml returns MissingPart, because lookup is case-sensitive); truncatedAndGarbageInputsAreCorrupt (the first 40 percent of a valid archive and a plain text byte array both fail to open with Corrupt). Compare error codes through static_cast to int inside QCOMPARE. Do not use QSKIP to hide any failure; every test must run.
