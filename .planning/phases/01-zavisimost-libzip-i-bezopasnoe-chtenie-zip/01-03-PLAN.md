<objective>
Expose the documents layer to the application as one function that takes a file path, reads the file with QFile (which handles Cyrillic paths on Windows), and returns either the three DOCX parts with Russian warning texts or one Russian error text. Every text names only the file, so no directory and no document content can leak into a message (D-04, D-05, SAFE-05 at this layer).

Purpose: SAFE-01 at the application boundary. The user-visible behavior of "not a DOCX", "damaged", "encrypted", "old .doc", "too large" and "no main text" is decided here, and it is tested with a Cyrillic directory name and with a no-write snapshot. This layer does not read or change the draft; a failed import has no side effect on any draft, because the draft is never passed in.

Output: DocumentImport.h and DocumentImport.cpp in the application layer, the document_import Qt Test target, and the CMake wiring that puts the application layer on top of resume_documents.

Tracer: Task 1 is the leading tracer. It runs one path end to end: file path, QFile read, readDocxParts, DocumentImport result, Russian text on failure. The Cyrillic-directory happy path and the NotZip message are its tests.

Reversibility: the ImportedDocx shape is what Phase 3 displays and what Phase 2 parses; it is rated costly and flagged on Task 1. The texts are reversible. No one-way decision is made here.

Decisions implemented here (see 01-CONTEXT.md): D-01 (refuse above 10 MiB before opening; the message states the limit), D-04 (Russian messages with a short cause and a hint), D-05 (file name only, never the full path), D-06 (a separate text for LegacyDoc and for Encrypted, and separate texts for NotZip, Corrupt, Limit and MissingPart), D-08 and D-09 (warnings returned in the result as texts; shown in Phase 3).

Note on style: the ResumeJson module returns std::optional with a QString error argument. This plan returns std::expected so the error can carry a typed result and a text. The documents layer already uses std::expected (plan 01-02). The mismatch with the existing ResumeJson style is intentional and recorded in the Phase 1 memory note.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-selected file path to DocumentImport | The path comes from the user; the file behind it is untrusted |
| DocumentImport to the UI and logs (Phase 3) | Only fixed texts with the file name cross this boundary |
| file system to the import function | Read-only access; the function must not create or modify anything |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Denial of service | Reading an oversized file fully into memory | high | mitigate | QFileInfo size check before QFile open (TooLarge, no read). The read is bounded to kMaxFileBytes plus one byte, so a file that grows after the check is still refused. Tests cover the boundary and the refusal. |
| T-01-10 | Information Disclosure | Full path or document content in an error or warning text | medium | mitigate | Texts are fixed strings with the file name from QFileInfo fileName only. The leak test plants a marker in the document and checks that neither the marker nor the directory path appears in any message. |
| T-01-11 | Tampering | Files created or modified during import | medium | mitigate | QFile is opened ReadOnly; the archive is opened read-only from memory; no temporary files are made. The snapshot test shows an identical directory state before and after all cases. |
| T-01-SC | Tampering | Package install (supply chain) | high | accept | This plan installs no package. The libzip package gate is in plan 01-01 Task 1. |
</threat_model>

Unreadable: Не удалось открыть файл «%1». Проверьте, что он существует и доступен для чтения. TooLarge: Файл «%1» больше %2 МБ. Уменьшите файл (например, удалите изображения) и повторите. MissingPart: В файле «%1» не найден текст резюме. Сохраните его как .docx в Word и повторите. Warning StylesPartMissing: В файле «%1» нет описания стилей: заголовки могут отображаться как обычный текст. Warning NumberingPartMissing: В файле «%1» нет описания нумерации: списки могут отображаться без маркеров и номеров. Map every DocxError value to its text through one switch with no default branch, so a new code without a text fails to compile under the warnings the build enables.

(4) readDocxFile, in this order: build a QFileInfo from the path and take fileName() for every message. If the path is not an existing regular file, return Unreadable. If the size reported by QFileInfo is greater than kMaxFileBytes, return TooLarge without opening the file (D-01, T-01-09). Open a QFile on the path with ReadOnly only; if the open fails, return Unreadable. Read at most kMaxFileBytes plus one bytes with QFile read. If the bytes read are larger than kMaxFileBytes, the file grew after the check: return TooLarge. Close the file. Pass the byte array by value to documents readDocxParts. On an error from readDocxParts return the text for that code. On success, move the three parts into ImportedDocx and produce one warning text per DocxWarning code in the list, in order. Do not log, do not print, and do not keep the path after the messages are built.

Test readsDocxFromCyrillicDirectory: build a stored archive with all three parts (Cyrillic text in each), write it into the subdirectory with QFile, call readDocxFile on the full path, and expect the document bytes to be identical and the warnings list to be empty.
