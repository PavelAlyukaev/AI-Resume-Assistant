# Project Research Summary

**Project:** AI Resume Assistant (milestone: read .docx and show text in a Qt window)
**Domain:** Windows desktop resume editor, C++23 / Qt 6 Widgets / MinGW, read-only DOCX text import
**Researched:** 2026-10-24
**Confidence:** MEDIUM

## Executive Summary

Этот этап — импорт DOCX только для чтения. `.docx` — это ZIP с частями OOXML. Принятый подход: открыть ZIP, прочитать `word/document.xml` (а также `styles.xml` и `numbering.xml` для заголовков и списков), потоково разобрать его в нейтральную модель документа и показать текст в окне Qt. Разбор живёт в новом слое `src/documents/`. Чтение файла и ограничения — в слое приложения. `MainWindow` только отображает результат. Разобранные данные — недоверенный ввод, поэтому на этом этапе они не попадают в `Resume` и SQLite.

Рекомендация: libzip (MSYS2) для контейнера, `QXmlStreamReader` для XML, собственная модель `Document` (абзац с уровнем заголовка и данными списка, таблица). Вывод — `QTextDocument`/`QPlainTextEdit`. Парсер — чистая функция над `QByteArray`, поэтому перенос в рабочий поток позже обойдётся дёшево. Безопасность — обязательное требование: ограничения размера, числа записей и коэффициента сжатия, отказ от любых DTD/ENTITY, без распаковки на диск, точный поиск `word/document.xml`.

Основные риски: (1) замена черновика может стереть несохранённые правки — в приложении нет флага «изменено» и обработчика закрытия; (2) libzip не установлен и не проверен (имя пакета, pkg-config, деплой DLL, списки установки в CI); (3) кириллица в содержимом и путях Windows; (4) углы OOXML (текстовые поля, content controls, исправления), где текст теряется молча, если его не считать и не показать.

## Key Findings

### Recommended Stack

Добавляется одна зависимость — libzip. Остальное уже подключено через Qt. pugixml (MIT) — запасной вариант, если потоковый обход станет громоздким. Приватный `QZipReader` Qt использовать нельзя.

**Core technologies:**
- libzip 1.11.4 (`mingw-w64-x86_64-libzip`, BSD-3): чтение записей ZIP с кодами ошибок. Поиск через `pkg_check_modules(... IMPORTED_TARGET libzip)`.
- `QXmlStreamReader` (QtCore, Qt 6.11.1 локально, минимум 6.7): потоковый разбор с пространствами имён, без новой зависимости.
- `QTextDocument`/`QTextCursor` или `QPlainTextEdit`: отображение. Генерированный HTML не использовать.

### Expected Features

**Must have (table stakes):**
- Открытие `.docx` через диалог выбора файла, пути как `QString` (кириллица в путях)
- Проверка ZIP и `word/document.xml` с понятными ошибками; определение зашифрованных файлов и старого `.doc`; пропуск файлов блокировки `~$`
- Тело в порядке документа: заголовки (по стилю, outlineLvl), маркированные и нумерованные списки с вложенностью, таблицы (строки, пустые ячейки, gridSpan, вложенные)
- Распаковка контейнеров: `w:hyperlink`, `w:ins`, `w:sdt`, `w:smartTag`, `w:fldSimple`; пропуск `w:del`/`w:delText`; изображения игнорируются
- Кириллица сохраняется точно; защита от zip-bomb; при неудачном открытии черновик не меняется
- Без молчаливой потери текста: пропущенные конструкции считаются и показываются в строке состояния; ошибки без персональных данных

**Should have (differentiators):**
- Содержимое текстовых полей (одно из Choice/Fallback), колонтитулы — один раз
- Однократная отмена замены черновика, структура заголовков, отображение символов маркеров

**Defer (v2+):**
- Старый `.doc`, DOCX с паролем, точная вёрстка, автоизвлечение этапов карьеры (Sprint 2), запись и экспорт (Sprint 4)

### Architecture Approach

Слои: `MainWindow` вызывает `DocumentImport::readFile(path)` (приложение: чтение файла, лимит 10 MiB, выбор по расширению), который вызывает `documents::docx::read(QByteArray, QString* error)` (новая статическая библиотека `resume_documents`: обёртка `ZipArchive` над libzip и `DocxReader`). Модель (`Paragraph`, `Table`, `Block`, `Document` с `sourceName` и `warnings`) отделена от `domain/Resume.h`. Ничего не записывается в хранилище. Сопоставление с `Resume`/`CareerStage` — этап Sprint 2.

**Major components:**
1. `ZipArchive` (documents): открытие из памяти, чтение одной именованной записи с ограничениями
2. `DocxReader` (documents): WordprocessingML → `Document`, предупреждения о неподдерживаемых конструкциях
3. `DocumentImport` (application): чтение файла, ограничения, выбор обработчика, безопасные ошибки
4. `MainWindow` (ui): диалог, предпросмотр только для чтения, предупреждения в строке состояния

### Critical Pitfalls

1. **Потеря данных при замене без подтверждения** — флаг `dirty_`, запрос при закрытии, однократная отмена, метка «импортировано, не сохранено»; также исправить существующий баг перезаписи в `selectStage`. См. Open Decisions.
2. **Zip bomb** — ограничения на реально распакованные байты (число записей, размер записи, общий размер, коэффициент сжатия только сверх порога); распаковывать только `document.xml`.
3. **XXE / расширение сущностей** — отклонять любые DTD-токены и `<!DOCTYPE` / `<!ENTITY`; без собственного resolver; без QtXml/libxml2.
4. **Кириллица/кодировка** — пути только как `QString`, декодирование оставить XML-читателю, нормализация NFC, синтетические кириллические фикстуры, без вывода в консоль.
5. **Приватность и сборка/упаковка** — никогда не логировать разобранный текст; только базовое имя файла; новый пакет в обоих списках установки CI; проверка установленного приложения из чистой папки.

## Implications for Roadmap

### Phase 1: DOCX reader core
**Rationale:** Чистый модуль без UI, несёт основной риск (безопасность, кодировка, OOXML). От него зависит всё остальное.
**Delivers:** библиотека `resume_documents`, `ZipArchive`, `DocxReader`, модель `Document`, `toPlainText`, тесты на синтетических фикстурах.
**Addresses:** порядок тела, заголовки, списки, таблицы, распаковка контейнеров, пропуск изображений, определение ошибок/шифрования/.doc, предупреждения.
**Avoids:** zip bomb, XXE, path traversal, кодировка, утечки приватных данных.

### Phase 2: Build, CI and packaging for libzip
**Rationale:** Должно появиться до или вместе с Phase 1, чтобы зависимость работала на ПК разработчика, в CI и в установщике.
**Delivers:** libzip установлен и подключён, списки установки CI обновлены, `DeployMinGWRuntime.cmake` проверен, запуск из чистой папки.
**Avoids:** сбои DLL вида «на моём ПК работает». Запасной вариант, если libzip недоступен: сырой inflate через zlib или miniz за тем же интерфейсом.

### Phase 3: Qt import UI and draft replacement
**Rationale:** Тонкий UI над проверенным ядром; решение о поведении замены уже принято (спрашивать перед заменой).
**Delivers:** пункт меню, диалог выбора файла, `DocumentImport`, предпросмотр, предупреждения в строке состояния, флаг изменений, запрос при закрытии, отмена (однократная), исправление `selectStage`; рабочий поток с счётчиком поколений, если тест на 10 MB подвешивает окно.
**Avoids:** потерю данных, зависание UI, утечку текста ошибок через `reportError`.

### Phase Ordering Rationale

- Сначала чтение (нет зависимости от UI); затем подключение зависимости (блокирует сборку); UI — последним (нужны оба предыдущих этапа и решение).
- Чистый модуль чтения оставляет открытыми потоки и повторное использование в CLI/вебе.
- Колонтитулы, текстовые поля и точность нумерации — дополнения v1.x к Phase 1, только если образцы резюме это подтвердят.

### Research Flags

Нужно углубить при планировании:
- **Phase 2:** пакет libzip, путь pkg-config и деплой DLL не проверены; подтвердить сборкой и `cmake --install`.
- **Phase 1:** особенности OOXML (названия стилей заголовков в русском интерфейсе, текстовые поля, `sdt`, объединённые ячейки) нужно проверить на наборе фикстур; поведение DTD в QXmlStreamReader — тест на Qt 6.11.1.

Стандартные шаблоны (исследование не нужно):
- **Phase 3:** меню, диалоги, предпросмотр и флаг изменений в Qt Widgets хорошо документированы; открытым остаётся только решение по поведению.

## Open Decisions

1. **Замена без подтверждения против потери данных — РЕШЕНО.** Пользователь выбрал «Спрашивать перед заменой». Уточнить, живёт ли черновик только в памяти UI или также в SQLite (сохранённая копия переживает замену; рискуют только несохранённые правки).
2. **libzip не проверен.** Не установлен; имя пакета `mingw-w64-x86_64-libzip` и версия 1.11.4 взяты из локальной базы синхронизации (возможно, устаревшей) и страницы пакета. Не подтверждены: разрешение pkg-config, подтягивание транзитивных DLL (gnutls, nettle, zstd и др.) деплоем `DeployMinGWRuntime.cmake`, размер установщика, списки установки CI. Вариант zlib raw inflate — запасной. Решить после пробной сборки и установки; читатель ZIP должен быть за `ZipArchive`, чтобы работал любой вариант.
3. **Текстовые поля и колонтитулы.** Здесь часто контактные данные. Рекомендация: в v1 считать предупреждениями, если образцы резюме не покажут обратного.
4. **Исправления (tracked changes):** рекомендуется принятый вид (оставлять `w:ins`, пропускать `w:del`). Нужно подтверждение.
5. **Числовые лимиты** (файл 10 или 20 MB, вывод 20 или 64 MB, 200k символов) в разных файлах различаются; это предложения. Выбрать один набор.
