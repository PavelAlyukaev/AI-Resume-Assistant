# Слой documents: контейнер DOCX

Слой читает контейнер DOCX из памяти, определяет, что за байты пришли, и возвращает три
части (`word/document.xml`, `word/styles.xml`, `word/numbering.xml`) или код ошибки.
Текст ошибки для пользователя здесь не формируется: он живёт в слое приложения.

## Состав

- `DocxTypes.h`: коды `DocxError`, коды `DocxWarning` и константы лимитов.
- `ZipArchive.h/.cpp`: read-only обёртка над libzip поверх `QByteArray` (pimpl, без типов libzip в заголовке).
- `DocxContainer.h/.cpp`: `readDocxParts` — классификация по сигнатуре и чтение трёх частей.

## Правила слоя

- **Только байты, без путей.** Функции принимают `QByteArray`, а не путь. Путь с кириллицей
  не передаётся в узкий API libzip на MinGW. Файл читает вызывающая сторона через `QFile`.
- **Ничего не пишется на диск.** Архив открывается с `ZIP_RDONLY`, распакованные данные
  остаются в памяти.
- **Читаются только три имени** из `word/`: точное имя, с учётом регистра. Другие записи не декодируются.
- **Без частичного результата (D-07).** Если любая часть не читается, возвращается код
  ошибки и не возвращается ни одного байта.
- **Тексты сообщений и имена файлов — в слое приложения.** Слой возвращает только коды;
  текст libzip не сохраняется и не возвращается.
- **Владение источником libzip.** Если `zip_open_from_source` завершился ошибкой, источник не
  освобождается (выбрана ветка (c) из плана 01-01). Это открытый вопрос владельца: возможна
  мелкая утечка на редком пути, двойного освобождения нет.
- **Структура до чтения (план 01-04).** При открытии сначала проверяется число записей
  (больше `kMaxEntries` — `Limit`), затем каждое имя читается один раз; повтор имени — `Corrupt`.
  Ни одна запись до этого не читается.
- **Коэффициент сжатия (план 01-04).** Проверка идёт по байтам, которые реально вернул
  `zip_fread`, и только после `kCompressionCheckAfterBytes`. Объявленный размер сжатых данных
  используется только в этом сравнении: он не выделяет память и не расширяет бюджет.
  Если libzip не сообщает размер сжатых данных, берётся 1 (проверка строже).

## Коды `DocxError`

| Код | Значение |
| --- | --- |
| `NotZip` | Вход не начинается ни с сигнатуры ZIP (локальный заголовок или пустой архив), ни с CFB; включая пустой вход. |
| `Corrupt` | Вход начинается с сигнатуры ZIP, но libzip его отвергает; запись повреждена (ошибка CRC и т. п.); в архиве два элемента с одним именем. |
| `Encrypted` | Контейнер CFB с потоком `EncryptedPackage` (зашифрованный DOCX) либо запись ZIP, для которой libzip требует пароль (нет пароля или неверный пароль). |
| `LegacyDoc` | Контейнер CFB без `EncryptedPackage`: старый бинарный `.doc`, переименованный в `.docx`. |
| `TooLarge` | Вход больше `kMaxFileBytes` (проверка на уровне контейнера; файловая проверка до открытия — план 01-03). |
| `Limit` | Распакованные данные превышают оставшийся бюджет `kMaxUnpackedBytes`; коэффициент сжатия превышает `kMaxCompressionRatio` после `kCompressionCheckAfterBytes`; записей больше `kMaxEntries` (при открытии). |
| `MissingPart` | В архиве нет `word/document.xml` (обязательная часть) либо имя содержит NUL. |

## Коды `DocxWarning`

Предупреждения не прерывают чтение. Список `warnings` содержит по одному коду на каждую
отсутствующую необязательную часть, поэтому его размер равен числу таких частей (D-08, D-09):

| Код | Значение |
| --- | --- |
| `StylesPartMissing` | Нет `word/styles.xml`; `stylesXml` пуст. |
| `NumberingPartMissing` | Нет `word/numbering.xml`; `numberingXml` пуст. |

## Константы лимитов

| Константа | Значение | Статус | Где действует и тесты |
| --- | --- | --- | --- |
| `kMaxFileBytes` | 10 MiB (D-01) | Действует (план 01-02 и 01-03) | `readDocxParts` дает `TooLarge` (`inputAboveFileLimitIsTooLarge`); файловая проверка до открытия в `DocumentImport` (`fileAboveLimitIsTooLargeBeforeOpen`). Чтение «MB» как MiB ждёт подтверждения владельца. |
| `kMaxUnpackedBytes` | 20 MiB, общий бюджет трёх частей за одно открытие | Действует (план 01-01 и 01-04) | `readEntry` (`readEntryEnforcesByteBudget`, `budgetBoundaryIsExact`); общий бюджет трёх частей (`sharedBudgetAcrossParts`). Охват D-02 как общего бюджета ждёт подтверждения владельца. |
| `kMaxEntries` | 1000 записей | Действует (план 01-04, значение планировщика) | `ZipArchive::open` (`tooManyEntriesIsLimit`, `exactlyMaxEntriesIsAccepted`). Ждёт подтверждения владельца. |
| `kMaxCompressionRatio` | 100:1 | Действует (план 01-04, значение планировщика) | `ZipArchive::readEntry` (`deflatedBombIsLimitedByRatio`; `storedLargeEntryIsNotRatioLimited` — несжатый элемент не ограничивается). Ждёт подтверждения владельца. |
| `kCompressionCheckAfterBytes` | 1 MiB | Действует (план 01-04, значение планировщика) | Порог, с которого включается проверка коэффициента. Ждёт подтверждения владельца. |
| `kMaxTextChars` | 200000 (D-03) | Не действует: Фаза 2 | Ограничение длины текста резюме; в этом слое не проверяется. |

«MB» в D-01 и D-02 читается как MiB (1024 × 1024 байта). Это чтение ждёт подтверждения владельца.
Значения `kMaxEntries`, `kMaxCompressionRatio` и `kCompressionCheckAfterBytes` выбрал планировщик,
не владелец. Их можно поменять в `DocxTypes.h`. `exactlyMaxEntriesIsAccepted` сверяет число записей
с `kMaxEntries`, а `tooManyEntriesIsLimit` использует литерал 1001: при смене константы его надо пересчитать.

## Что не входит в слой

- Разбор XML и содержимого (Фаза 2).
- Пользовательские тексты ошибок и вывод имени файла (слой приложения, план 01-03).
- Любая запись на диск.
