# Слой documents: контейнер DOCX

Слой читает контейнер DOCX из памяти, определяет, что за байты пришли, читает три части
(`word/document.xml`, `word/styles.xml`, `word/numbering.xml`) и разбирает тело документа в модель
(`readDocxContent` возвращает `DocxDocument`). Результат или код ошибки. Текст ошибки для пользователя
здесь не формируется: он живёт в слое приложения.

## Состав

- `DocxTypes.h`: коды `DocxError`, коды `DocxWarning` и константы лимитов.
- `ZipArchive.h/.cpp`: read-only обёртка над libzip поверх `QByteArray` (pimpl, без типов libzip в заголовке).
  `entryNames()` возвращает только имена записей, сохранённые при открытии.
- `DocxContainer.h/.cpp`: `readDocxParts` — классификация по сигнатуре, чтение трёх частей и счёт
  колонтитулов и комментариев по именам.
- `DocxModel.h`: модель документа (`Paragraph`, `Table`, `TableRow`, `TableCell`, `Block`, `DocxDocument`).
- `DocxContent.h/.cpp`: `readDocxContent` — разбор стилей, нумерации и тела в модель.

## Правила слоя

- **Только байты, без путей.** Функции принимают `QByteArray`, а не путь. Путь с кириллицей
  не передаётся в узкий API libzip на MinGW. Файл читает вызывающая сторона через `QFile`.
- **Ничего не пишется на диск.** Архив открывается с `ZIP_RDONLY`, распакованные данные
  остаются в памяти.
- **Читаются только три имени** из `word/`: точное имя, с учётом регистра. Другие записи не декодируются.
  `word/_rels` не читается (T-02-13). Колонтитулы (`word/header<N>.xml`, `word/footer<N>.xml`) и
  `word/comments.xml` только считаются по имени (см. ниже); их байты не читаются.
- **Без частичного результата (D-07).** Если любая часть не читается, возвращается код
  ошибки и не возвращается ни одного байта.
- **Тексты сообщений и имена файлов — в слое приложения.** Слой возвращает только коды;
  текст libzip не сохраняется и не возвращается.
- **Владение источником libzip.** Если `zip_open_from_source` завершился ошибкой, источник не
  освобождается (выбрана ветка (c) из плана 01-01). Это открытый вопрос владельца: возможна
  мелкая утечка на редком пути, двойного освобождения нет.
- **Структура до чтения (план 01-04).** При открытии сначала проверяется число записей
  (больше `kMaxEntries` — `Limit`), затем каждое имя читается один раз; повтор имени — `Corrupt`.
  Ни одна запись до этого не читается.
- **Коэффициент сжатия (план 01-04).** Проверка идёт по байтам, которые реально вернул
  `zip_fread`, и только после `kCompressionCheckAfterBytes`. Объявленный размер сжатых данных
  используется только в этом сравнении: он не выделяет память и не расширяет бюджет.
  Если libzip не сообщает размер сжатых данных, берётся 1 (проверка строже).

## Правила чтения содержимого (план 02-04)

- **Проверка до разбора.** Каждая из трёх частей проверяется по токенам: DOCTYPE дает `UnsafeXml`
  до раскрытия сущностей, объявленная кодировка вне UTF-8 и UTF-16 дает `UnsupportedEncoding`.
  Частичного результата нет: при любом коде ошибки модель не возвращается.
- **Текст только из `w:t`.** Адреса гиперссылок не выводятся, выводится только текст между тегами
  (T-02-13). Пробелы внутри `w:t` сохраняются точно; пробелы между элементами отбрасываются.
- **`mc:AlternateContent`** читается по первой ветке `mc:Choice`; остальные ветки пропускаются.
  `mc:Fallback` читается только тогда, когда перед ним не было `mc:Choice` (A2).
- **Символы.** `w:tab` и `w:ptab` дают табуляцию; `w:br` и `w:cr` дают перевод строки;
  `w:noBreakHyphen` дает U+2011; `w:softHyphen` дает U+00AD.
- **Удалённые исправления не выводятся.** `w:del`, `w:moveFrom`, `w:delText` и `w:delInstrText`
  пропускаются без предупреждения (T-02-09). Вставки (`w:ins`, `w:moveTo`) выводятся.
- **Пропуски считаются, содержимое не читается.** Рисунки и объекты дают `ImageSkipped`, текстовые
  поля (`txbxContent`) дают `TextBoxSkipped`, `w:sym`, сноски, концевые сноски и неизвестные элементы
  с текстом дают `OtherSkipped`. Одно предупреждение на каждый экземпляр, в порядке документа.
- **Колонтитулы и комментарии** считаются по именам записей ZIP с точным шаблоном (с учётом регистра):
  `word/header<цифры>.xml` и `word/footer<цифры>.xml` дают по одному `HeaderFooterSkipped`;
  точное имя `word/comments.xml` дает один `OtherSkipped`. Байты этих записей не читаются (D-10),
  поэтому повреждённая полезная нагрузка не даёт ошибку импорта.
- **Нумерация.** Маркированный список выводится символом U+2022. Десятичная нумерация с `lvlText` `%1.`
  выводится как `N.` без предупреждения. Формат, который не воспроизводится (не маркер и не десятичный,
  либо десятичный с другим `lvlText`), выводится как `N.` и даёт один `ListFormatApproximated` на numId (OQ5).

## Коды `DocxError`

| Код | Значение |
| --- | --- |
| `NotZip` | Вход не начинается ни с сигнатуры ZIP (локальный заголовок или пустой архив), ни с CFB; включая пустой вход. |
| `Corrupt` | Вход начинается с сигнатуры ZIP, но libzip его отвергает; запись повреждена (ошибка CRC и т. п.); в архиве два элемента с одним именем. |
| `Encrypted` | Контейнер CFB с потоком `EncryptedPackage` (зашифрованный DOCX) либо запись ZIP, для которой libzip требует пароль (нет пароля или неверный пароль). |
| `LegacyDoc` | Контейнер CFB без `EncryptedPackage`: старый бинарный `.doc`, переименованный в `.docx`. |
| `TooLarge` | Вход больше `kMaxFileBytes` (проверка на уровне контейнера; файловая проверка до открытия — план 01-03). |
| `Limit` | Четыре случая: распакованные данные превышают оставшийся бюджет `kMaxUnpackedBytes`, коэффициент сжатия превышает `kMaxCompressionRatio` после `kCompressionCheckAfterBytes`, записей больше `kMaxEntries` (при открытии); длина текста резюме больше `kMaxTextChars`; вложенность глубже `kMaxNestingDepth`; число узлов модели больше `kMaxModelNodes`. Текст в приложении один для всех случаев. |
| `MissingPart` | В архиве нет `word/document.xml` (обязательная часть) либо имя содержит NUL. |
| `UnsafeXml` | DOCTYPE в любой из трёх частей (с сущностями или без): отказ до раскрытия сущностей (SAFE-03). |
| `UnsupportedEncoding` | Объявленная в XML кодировка не UTF-8 и не UTF-16 (OQ3). |

## Коды `DocxWarning`

Предупреждения не прерывают чтение. Список `warnings` содержит по одному коду на каждый экземпляр
пропуска или приближения, поэтому его размер равен числу таких экземпляров (D-08, D-09):

| Код | Значение |
| --- | --- |
| `StylesPartMissing` | Нет `word/styles.xml`; `stylesXml` пуст. |
| `NumberingPartMissing` | Нет `word/numbering.xml`; `numberingXml` пуст. |
| `ListFormatApproximated` | Нумерация оформлена иначе, чем `N.` или маркер; выводится упрощённо. Один код на каждый numId (OQ5). |
| `ImageSkipped` | Рисунок, фигура или встроенный объект; содержимое не показано, текст вокруг сохранён (DOCX-07). Один код на экземпляр. |
| `TextBoxSkipped` | Текстовое поле (`txbxContent`); содержимое не показано (SAFE-04). Один код на экземпляр. |
| `OtherSkipped` | `w:sym`, сноска или концевая сноска, неизвестный элемент с текстом; также `word/comments.xml` (один код на часть, OQ10). Один код на экземпляр. |
| `HeaderFooterSkipped` | Часть `word/header<N>.xml` или `word/footer<N>.xml`; считается по имени, не читается (OQ2). Один код на часть. |

## Константы лимитов

| Константа | Значение | Статус | Где действует и тесты |
| --- | --- | --- | --- |
| `kMaxFileBytes` | 10 MiB (D-01) | Действует (план 01-02 и 01-03) | `readDocxParts` дает `TooLarge` (`inputAboveFileLimitIsTooLarge`); файловая проверка до открытия в `DocumentImport` (`fileAboveLimitIsTooLargeBeforeOpen`). Чтение «MB» как MiB ждёт подтверждения владельца. |
| `kMaxUnpackedBytes` | 20 MiB, общий бюджет трёх частей за одно открытие | Действует (план 01-01 и 01-04) | `readEntry` (`readEntryEnforcesByteBudget`, `budgetBoundaryIsExact`); общий бюджет трёх частей (`sharedBudgetAcrossParts`). Охват D-02 как общего бюджета ждёт подтверждения владельца. |
| `kMaxEntries` | 1000 записей | Действует (план 01-04, значение планировщика) | `ZipArchive::open` (`tooManyEntriesIsLimit`, `exactlyMaxEntriesIsAccepted`). Ждёт подтверждения владельца. |
| `kMaxCompressionRatio` | 100:1 | Действует (план 01-04, значение планировщика) | `ZipArchive::readEntry` (`deflatedBombIsLimitedByRatio`; `storedLargeEntryIsNotRatioLimited` — несжатый элемент не ограничивается). Ждёт подтверждения владельца. |
| `kCompressionCheckAfterBytes` | 1 MiB | Действует (план 01-04, значение планировщика) | Порог, с которого включается проверка коэффициента. Ждёт подтверждения владельца. |
| `kMaxTextChars` | 200000 (D-03), в UTF-16 единицах | Действует (фаза 2, план 02-01) | `readDocxContent`: проверка во время накопления текста (`textLimitBoundary`); через `DocumentImport::readDocxFile` даёт текст о лимите с именем файла (`overTextLimitGivesLimitText`). |
| `kMaxModelNodes` | 50000 (OQ9, значение планировщика) | Действует (фаза 2, план 02-01; счёт таблиц в 02-03) | `readDocxContent`: абзацы, таблицы, строки и ячейки; `nodeLimitBoundary`. Ждёт подтверждения владельца. |
| `kMaxNestingDepth` | 64 (OQ7, значение планировщика) | Действует (фаза 2, план 02-03) | `readDocxContent`: счётные элементы (`w:tbl`, `w:sdt`, `w:customXml`, `w:hyperlink`, `w:ins`, `w:moveTo`, `w:smartTag`, `w:fldSimple`, выбранная ветка `mc:AlternateContent`); T-02-08. Ждёт подтверждения владельца. |

«MB» в D-01 и D-02 читается как MiB (1024 × 1024 байта). Это чтение ждёт подтверждения владельца.
Значения `kMaxEntries`, `kMaxCompressionRatio` и `kCompressionCheckAfterBytes` выбрал планировщик,
не владелец. Их можно поменять в `DocxTypes.h`. `exactlyMaxEntriesIsAccepted` сверяет число записей
с `kMaxEntries`, а `tooManyEntriesIsLimit` использует литерал 1001: при смене константы его надо пересчитать.

## Что не входит в слой

- Чтение колонтитулов, комментариев, сносок, `word/_rels` и адресов гиперссылок (вне v1; только счёт или
  отказ, см. выше).
- Пользовательские тексты ошибок и предупреждений и вывод имени файла (слой приложения, планы 01-03 и 02-04).
- Любая запись на диск.
